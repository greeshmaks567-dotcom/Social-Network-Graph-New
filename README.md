# Social-Network-Graph-New
DESCRIPTION

A graph is a non-linear data structure that is used to represent relationships or connections between different objects. In a social network, each person can be represented as a vertex, while a friendship or connection between two people can be represented as an edge. Graphs are widely used in social networking applications because they provide an efficient way to represent relationships between users. In this experiment, a small social network is represented using a graph. The vertices of the graph are A, B, C, D, E, and F. The connections between the vertices are A–B, A–C, B–D, B–E, C–F, and E–F. Since the connections are considered to be mutual, the graph is an undirected graph. This means that if A is connected to B, then B is also connected to A.

The main objective of this experiment is to implement the given social network using two different graph representation techniques, namely the adjacency matrix and the adjacency list. After constructing both representations, Breadth First Search and Depth First Search are performed starting from vertex A. A search operation is also performed to locate a specified vertex. Finally, the two representations are analysed and compared based on their memory requirements, traversal behaviour, searching operations, edge-checking operations, and time complexity. The purpose of this comparison is to determine which representation is more appropriate for a sparse social network.

An adjacency matrix is a graph representation technique that uses a two-dimensional array to store the connections between vertices. In an adjacency matrix, each row and column represents a vertex. If two vertices are directly connected, the corresponding position in the matrix contains the value 1. If there is no direct connection between the two vertices, the corresponding position contains the value 0. Since the given graph contains six vertices, an adjacency matrix of size six by six is required. The matrix therefore contains thirty-six positions. Although only the actual connections need to be represented, the matrix reserves space for every possible pair of vertices. This makes the adjacency matrix simple and easy to understand, but it may use more memory when the graph contains a large number of vertices and relatively few edges.

One major advantage of the adjacency matrix is that it provides very fast edge checking. For example, if we want to check whether vertices E and F are directly connected, the program can directly access the position corresponding to E and F in the matrix. If the value is 1, the vertices are connected; if the value is 0, there is no direct connection. Therefore, checking whether an edge exists in an adjacency matrix takes constant time, or O(1). This is particularly useful when an application performs a large number of direct connection queries.

The second representation used in this experiment is the adjacency list. An adjacency list stores a list of all the neighbouring vertices for each vertex. Instead of storing every possible connection, it stores only the connections that actually exist. In this network, vertex A is connected to B and C, so the adjacency list for A contains B and C. Vertex B is connected to A, D, and E. Vertex C is connected to A and F. Vertex D is connected only to B. Vertex E is connected to B and F, while vertex F is connected to C and E. Because only the actual connections are stored, an adjacency list generally requires less memory than an adjacency matrix when the graph is sparse.

After constructing the graph, Breadth First Search is performed starting from vertex A. Breadth First Search, commonly called BFS, is a graph traversal technique that visits vertices level by level. It normally uses a queue data structure. The algorithm first visits the starting vertex A. It then visits the vertices directly connected to A, which are B and C. After that, it processes B and visits its unvisited neighbours D and E. It then processes C and visits F. The resulting BFS traversal is A, B, C, D, E, F. BFS is useful in social networks because it can be used to explore users according to their distance from a particular user. For example, users directly connected to A can be considered first-level connections, while users reached through another person can be considered connections at a greater level.

Depth First Search, commonly called DFS, is another graph traversal method used in this experiment. DFS explores one path as deeply as possible before returning to an earlier vertex and exploring another path. It can be implemented using recursion or a stack. Starting from A, the traversal first moves from A to B. From B, it moves to D. Since D has no unvisited neighbour, the algorithm returns to B and then visits E. From E, it moves to F, and from F it reaches C. After all vertices have been visited, the DFS traversal is A, B, D, E, F, C, assuming that neighbouring vertices are processed in alphabetical order. DFS is useful for exploring connected components, finding paths, and analysing relationships within a network.

The experiment also includes a vertex search operation. A specified vertex can be located by examining the vertex labels. For example, if the required vertex is E and the labels are stored in the order A, B, C, D, E, and F, a simple linear search first checks A, then B, then C, then D, and finally E. The vertex E is therefore found after five comparisons. The number of comparisons depends on the position of the required vertex. In the worst case, all vertices may have to be checked before the required vertex is found. Therefore, a simple linear search has a time complexity of O(V), where V represents the number of vertices.

Edge checking behaves differently in the two representations. In an adjacency matrix, an edge can be checked directly by accessing the appropriate matrix position. Therefore, edge checking requires constant time, O(1). In an adjacency list, the list of neighbours of one vertex must be examined to determine whether the other vertex is present. The time required depends on the number of neighbours of the vertex being checked. Therefore, edge checking using an adjacency list generally takes O(degree of the vertex) time. For example, to determine whether E is connected to F, the program examines the neighbours stored for E until F is found.

The space requirement is another important difference between the two representations. An adjacency matrix requires O(V²) memory because it stores a position for every possible pair of vertices. For six vertices, thirty-six matrix positions are required. Many of these positions represent connections that do not exist. On the other hand, an adjacency list requires O(V + E) space because it stores the vertices and their actual edges. Since the given graph has six vertices and six edges, the adjacency list stores considerably less information than the complete matrix. This difference becomes much more significant when the number of vertices increases.

The time complexity of graph traversal also differs between the two representations. When BFS or DFS is performed using an adjacency matrix, the algorithm may have to examine an entire row of the matrix for every vertex in order to identify its neighbours. Therefore, the time complexity is O(V²). When BFS or DFS is performed using an adjacency list, the algorithm examines each vertex and each actual edge only as required. Therefore, the time complexity is O(V + E). This makes the adjacency list more efficient for sparse graphs, where the number of edges is much smaller than the number of possible edges.

The given social network can be considered relatively sparse because there are only six actual connections between the six vertices. A complete undirected graph with six vertices could have fifteen possible edges, but the given network contains only six edges. Consequently, a large number of possible connections do not exist. An adjacency matrix still allocates space for all possible vertex pairs, whereas an adjacency list stores only the connections that are actually present. Therefore, the adjacency list makes better use of memory in this situation.

Based on the execution of BFS and DFS, both graph representations are capable of producing the same traversal order when the neighbouring vertices are processed in the same order. Starting from A, BFS visits A, B, C, D, E, and F. DFS visits A, B, D, E, F, and C. The difference between the two traversals occurs because BFS explores the graph level by level, whereas DFS explores as deeply as possible before backtracking.

The adjacency matrix has the advantage of simple implementation and constant-time edge checking. It can be particularly useful for dense graphs or applications where checking whether two particular vertices are directly connected is a frequent operation. However, its major disadvantage is its O(V²) space requirement, which can become inefficient when the graph contains many vertices but relatively few edges.

The adjacency list is more suitable when the graph is sparse. It stores only the actual connections, requires O(V + E) space, and allows BFS and DFS to be performed in O(V + E) time. Although checking a particular edge may require searching through a vertex's neighbour list, this is usually acceptable for sparse networks because each vertex has relatively few neighbours.

Therefore, based on the execution results and complexity analysis, the adjacency list is more appropriate for the given sparse social network. It provides better memory utilization and more efficient traversal because the algorithms process only the connections that actually exist. The adjacency matrix is still useful when fast O(1) edge checking is required, but for a sparse social network with relatively few connections, the adjacency list provides a more efficient overall representation.

This experiment demonstrates that the choice of graph representation depends on the structure of the graph and the operations that need to be performed. For dense graphs, an adjacency matrix can be suitable because most possible connections exist and the memory allocated by the matrix is effectively utilized. For sparse graphs, an adjacency list is generally preferred because it avoids storing unnecessary information and provides efficient graph traversal. Thus, for the social network considered in this experiment, the adjacency list is the more suitable representation.
